# stream-mediary 需求规格（Requirements）

> SDD 第一层文档。定义产品范围、用户故事与可测试的验收准则。
> 版本：v1.0 ｜ 平台：Android / iOS / Windows / macOS（一套代码）

## 1. 产品概述

stream-mediary 是一个跨平台 M3U8（HLS）媒体下载客户端。用户输入 m3u8 地址，应用解析播放列表、多线程下载全部分片、按需解密并合并为可播放的单个视频文件，同时提供下载管理、历史记录、本地播放与软件设置能力。

### 1.1 目标用户
需要保存/离线观看 HLS 流媒体内容的普通用户，具备基本的 URL 概念。

### 1.2 设计原则
- 简洁友好：主流程（输入地址 → 预览 → 下载）三步以内完成
- Material 3：遵循最新 Material 设计规范，支持亮/暗/跟随系统主题
- 平台自适应：窄屏（移动）底部导航，宽屏（桌面）侧边导航
- 一套代码：四平台共享全部 Dart 代码，平台差异收敛在适配层

## 2. 功能需求

### FR-1 新建下载
**用户故事**：作为用户，我输入 m3u8 地址并可配置高级选项，解析后确认开始下载。

- FR-1.1 URL 输入框，支持粘贴，实时校验格式（允许 http/https 的 m3u8 或任意可解析的播放列表地址）
- FR-1.2 高级选项（可折叠）：
  - 自定义 HTTP 请求头：键值对编辑器，可增删多行，全程随请求携带
  - 自定义 KEY（hex）与 IV（hex）：用于覆盖源自带的加密参数
- FR-1.3 解析预览：点击解析后展示分片数量、总时长、是否加密（算法）、估算大小；若为 master playlist（多清晰度），列出清晰度/带宽供单选
- FR-1.4 保存目录选择（桌面端任意目录；移动端使用应用目录）
- FR-1.5 确认后创建下载任务并跳转下载管理页

**验收准则**
- AC-1.1 非法地址（空、非 URL）时解析按钮禁用或给出明确错误提示
- AC-1.2 携带自定义头请求受保护源时解析成功；不携带时返回 403 并有友好提示
- AC-1.3 master playlist 正确列出全部清晰度选项，默认选中带宽最高项
- AC-1.4 预览信息（分片数/时长/加密状态）与源实际内容一致
- AC-1.5 确认下载后任务出现在下载管理页且立即开始调度

### FR-2 下载管理
**用户故事**：作为用户，我能看到每个任务的实时进度，并控制任务。

- FR-2.1 任务卡片展示：标题、状态、进度条、分片进度（n/N）、下载速度、已下载大小、剩余时间估算
- FR-2.2 并发下载：任务级并发数可配置（默认 3），任务内分片并发（默认 8）
- FR-2.3 控制操作：暂停、恢复、取消（需确认）、失败后重试
- FR-2.4 断点续传：应用重启后自动恢复未完成任务，已完成分片不重复下载
- FR-2.5 下载完成后自动触发合并（见 FR-3）

**验收准则**
- AC-2.1 100+ 分片的明文视频可完整下载成功
- AC-2.2 下载过程中杀掉应用并重启，任务自动续传，已下载分片不重复请求
- AC-2.3 暂停后网络请求停止；恢复后从断点继续；取消后任务与临时分片被清理
- AC-2.4 单分片失败自动重试（最多 3 次指数退避）；任务整体失败可一键重试
- AC-2.5 进度与速度实时刷新（≤1 秒延迟），UI 不卡顿

### FR-3 分片合并
**用户故事**：作为用户，下载完成后我得到一个可直接播放的视频文件。

- FR-3.1 默认合并方式：按序拼接全部分片为单个 .ts 文件
- FR-3.2 若检测到本机 ffmpeg（或用户在设置中指定路径），无损 remux 为 .mp4（-c copy）
- FR-3.3 remux 失败时自动回退保留 .ts 产物
- FR-3.4 合并过程展示进度，合并中任务不可被暂停
- FR-3.5 合并产物路径持久化，供播放与"打开所在目录"使用

**验收准则**
- AC-3.1 拼接产物与分片按序 cat 的结果逐字节一致
- AC-3.2 有 ffmpeg 环境时产物为 .mp4 且可播放；无 ffmpeg 时产物为 .ts 且可播放
- AC-3.3 人为构造 remux 失败（损坏分片）时回退 .ts 且任务不崩溃
- AC-3.4 合并进度实时可见

### FR-4 下载历史
**用户故事**：作为用户，我能查看所有历史任务并管理它们。

- FR-4.1 历史列表：完成/失败/已取消任务，展示标题、时间、大小、状态
- FR-4.2 操作：播放（仅已完成）、重新下载、打开文件所在目录（桌面端）、删除记录（含确认）
- FR-4.3 历史记录跨应用重启持久化

**验收准则**
- AC-4.1 重启应用后历史记录完整保留
- AC-4.2 已完成任务可直接进入播放页播放产物
- AC-4.3 删除记录时二次确认；删除后列表即时更新
- AC-4.4 重新下载会以相同参数创建新任务

### FR-5 播放
**用户故事**：作为用户，我能在应用内播放已下载的视频。

- FR-5.1 播放本地 .ts 与 .mp4 文件
- FR-5.2 控制条：播放/暂停、进度拖动、时间显示、音量、全屏
- FR-5.3 桌面端支持键盘快捷键（空格播放/暂停、方向键快进快退）

**验收准则**
- AC-5.1 应用下载的 .ts 与 .mp4 产物均可正常播放，音画同步
- AC-5.2 进度条拖动后播放位置正确跳转
- AC-5.3 桌面端快捷键生效

### FR-6 软件设置
**用户故事**：作为用户，我能按偏好配置应用。

- FR-6.1 任务并发数（1–16，默认 3）
- FR-6.2 默认保存目录
- FR-6.3 主题模式：跟随系统 / 亮色 / 暗色
- FR-6.4 合并偏好：仅 TS / 优先 MP4（有 ffmpeg 时）
- FR-6.5 ffmpeg 路径：自动探测状态展示 + 手动指定
- FR-6.6 关于信息（版本号）

**验收准则**
- AC-6.1 所有设置项修改后立即持久化并端到端生效（重启不丢失）
- AC-6.2 主题切换即时生效无需重启
- AC-6.3 ffmpeg 探测状态与实际环境一致；手填错误路径时给出提示

## 3. 非功能需求

- NFR-1 性能：下载/解密/合并全链路流式处理，内存占用恒定，不随文件大小增长
- NFR-2 兼容：Android（minSdk 24）/ iOS / Windows / macOS 一套代码，行为一致
- NFR-3 稳定：单分片失败不影响整体任务；任何异常有用户可见的友好提示
- NFR-4 可测：核心引擎（解析/解密/合并/调度）为纯 Dart 模块，单元测试覆盖率 ≥70%
- NFR-5 国际化：支持中文（默认）与英文

## 4. 范围外（v1 不做）

- HLS 直播流录制（仅点播）
- 非标准私有加密（除 AES-128/192/256-CBC 外）
- iOS 后台下载（受系统限制，采用前台下载 + 断点续传兜底）
- 字幕/多音轨选择
- 浏览器插件式地址嗅探
